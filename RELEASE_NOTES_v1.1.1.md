# v1.1.1 local maintenance candidate: checksum and reproducibility infrastructure

This document describes an IMPL-03 local implementation candidate based on
v1.1.0, commit 11e6d49cc66994f5dce67012628376e28b2f75de.
The label v1.1.1 is a local candidate name only. It is not a created or reserved
remote tag, a published release, or approval to publish.

## Correction basis

The frozen RAW-BYTE-AUDIT-01 and CORRECTION-DESIGN-02 establish the maintenance
scope: platform-dependent text serialization and checkout newline conversion
caused generated hashes and repository Git-blob bytes to use inconsistent byte
bases. The previous output validator computed hashes from current outputs and
rewrote current-run manifests without comparing them with immutable expected
release hashes. The correction concerns byte identity and verification metadata.

## Candidate changes

- Repository .gitattributes fixes canonical LF for text and preserves binary files.
- CSV writers explicitly use lineterminator="\n" with newline="".
- JSON and generated text use exact UTF-8 bytes without BOM or platform newline translation, preserving existing numeric formatting, key order and trailing-newline policy.
- A separate frozen expected-output identity records the ten parent Git-blob sizes and SHA-256 hashes; the validator compares current bytes with that authority and fails on mismatch.
- Current-run manifests remain descriptive. Validation does not rewrite the immutable expected file.
- The release inventory generator reads exact staged or explicitly selected Git-tree blobs. Its checksum index covers all tracked regular files except itself, including the new inventory and manifest and the unchanged historical v1.1.0 indexes.
- Repository CI specifies Windows and Linux byte-identity checks. Local test availability and results are recorded in the separate IMPL-03 evidence package.

The acceptance target is regenerated byte parity with all ten existing v1.1.0
Git blobs, together with scientific semantic parity. Required negative evidence
includes a changed output byte, an appended newline, and a changed expected hash
all failing validation, plus repeated validation leaving expected bytes unchanged.
This note does not independently certify those test results or imply Linux ran.

## Preserved science and history

MFP weights and intercept, Gaussian-window parameters, drying-route score map,
capillary equation and thresholds, OPR rules, seed and candidate data, scores and
rankings remain unchanged. This is no algorithm, dataset, score or ranking
correction. The synthetic-curated workflow remains a deterministic demonstration;
the maintenance work makes no new model-validation or experimental-synthesis claim.
Source-grounded scoring, ranking, training and synthetic imputation remain closed.

The v1.1.0 tag and history and its three historical root index files are preserved.
New indexes have v1.1.1 names and an explicit Git-blob byte basis. No GitHub write,
tag creation, release publication, Zenodo/DOI operation, manuscript v46.1 edit or
v47 creation is authorized or represented by this candidate.

## Remaining gates

The result package is for independent IMPL-03-AUDIT-01. That audit must recheck
parent identity, ten-output Git-blob and semantic parity, scientific freeze,
negative tests, immutable expected authority and exact-tree checksum coverage.
If Linux execution is unavailable, the local result must retain
WARNING_LOCAL_IMPLEMENTATION_PASS_LINUX_TEST_NOT_RUN; a CI specification alone
does not constitute a completed cross-platform test. Only after independent audit
PASS may separate user authorization for a real GitHub v1.1.1 release be considered.
